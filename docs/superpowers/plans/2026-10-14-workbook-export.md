# Multi Site Workbook Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Download a reviewed Excel snapshot with one worksheet per selected saved Jira entry (including entries sharing a hostname) for manual SharePoint upload/sharing.

**Architecture:** Collect selected sites sequentially using explicit credentials and read-only metadata access, preserving the application's active site. Keep a bounded server preview snapshot; write a workbook from that snapshot and the user's row exclusions without re-fetching data at download time.

**Tech Stack:** Existing Express, SQLite and React; approved `pg`; approved server-side `exceljs` 4.4.0 with scoped `uuid` 11.1.1 override in E2.

**Spec:** [Approved design](../specs/2026-10-14-application-review-design.md); [shared contracts](2026-10-14-application-review.md). Depends on S1–S3 and D1/D2; D3 UI need not be finished.

## Global Constraints

- Each selected saved entry receives its own worksheet, including entries with the same hostname; there is no required combined task sheet.
- Locally saved metadata is the default; team-database metadata is an explicit option when available.
- Keep selected-source planning metadata separate. Show supplemental local notes and selected Team notes in separate labeled columns; never substitute values. Preserve the active Jira site.
- The workbook is a dated snapshot, not a live connection, backup/restore format, or import template.
- No direct SharePoint upload, images/attachment binaries, personal To Dos, credentials, or local paths.
- No hand-built spreadsheet engine or hidden developer Python dependency; company SonarQube remains required before merge.

## Review Focus

1. Saved entries share a hostname and issue key → E1/E2 preserve instanceId, separate local stores/sheets, and independent exclusions.
2. Team source becomes unavailable halfway through collection → E1 reports it without borrowing local values.
3. One site fails or hits a result limit → E1/E3 require explicit partial-download consent.
4. Text starts `=`, `+`, `-`, or `@` → E2 writes string cells, never formula objects.
5. Long/colliding sheet names or oversized notes → E2 produces deterministic valid names and rejects oversized cells rather than truncating.

## Binding export contracts (2026-10-14 final clarification)

- Preserve `instanceId`, `displayName`, canonical `siteHost` throughout; one distinct saved entry per sheet even when host/key match. Reject duplicate selected IDs. Exclusions must match all of `{instanceId,siteHost,issueKey}` in the server-held snapshot.
- Selected Local/Team controls Docket priority, Now/Next, planning, decision fields and internal `note`. Workbook output uses separate `localNote` and `teamNote`. Local notes always belong to that saved entry's SQLite file; Team identity stays `(siteHost,issueKey)`. Local mode never queries Team. Team failure fails the site with no local fallback.
- `localNoteStatus:'available'|'unavailable'`: available empty notes are `""`; unavailable is `localNote:null`. Successful Team metadata plus unreadable supplemental local notes is partial. For explicit project scope only, missing saved SQLite mappings may use Jira built-in identity/status/assignee/due fields, with no inferred custom mappings. Missing saved-preset store cannot resolve that scope and fails the entry. Selected Local with missing/unmigrated schema fails without writing or migrating during export.
- `latestJiraComment:{text,author,createdAt}|null`, `jiraCommentStatus:'available'|'none'|'unavailable'`. Fetch only after scope and selected-source filters: `/rest/api/3/issue/{encodedKey}/comment?startAt=0&maxResults=1&orderBy=-created`. Latest means creation, never last edited. Use captured explicit credentials and existing S2 transport/allowlist. Reuse ADF text conversion preserving line breaks; include displayName only, no email/raw account ID/metadata blob. Unknown author/date is null. Preserve supplied timestamp timezone. Empty successful page is none; denied/timeout/inconsistent page or declared ordering is unavailable and makes site partial while retaining the task. No all-history fetch, edit/import behavior, or download re-fetch. Preview, Overview and sheet say **Latest Jira comment only**.
- Sequential collection uses S2 request timeouts and one collection deadline `DOCKET_EXPORT_TIMEOUT_MS`, default 120000, positive integer capped 600000. Check elapsed time as well as cancellation. Stop subsequent scopes/search/metadata/comments on deadline; release leases/handles. PostgreSQL keeps D1's finite statement timeout; this does not promise immediate in-flight query cancellation. Preserve assembled source-verified export rows and mark uncollected comments/local notes unavailable; unfinished sites are partial/failed explicitly. Search hits before selected metadata/filter evaluation are provisional: if deadline interrupts search, keep safe `searchedCount`, fail the entry with no rows and a before-metadata explanation. User cancellation discards the entire preview.
- Hold registry identity/deletion leases only for selected instance IDs during collection; unrelated registry operations and active-site switching remain available. Local reads are synchronous/read-only and copied into plain values before closing.
- Default/capped search limit 5000 per entry (`DOCKET_EXPORT_MAX_ROWS_PER_SITE`, positive integer). Missing completion evidence at the limit is partial. Snapshot store: 3 live/in-flight previews, 15 minutes, total serialized snapshots 25 MiB, no eviction/truncation to fit. Each stored snapshot is independent of later source edits and public clones. Reject oversized snapshots with narrower-filter guidance. A cell exceeding Excel's limit can remain in an otherwise fitting snapshot: E2 validates cells after exclusions and identifies affected row/field, allowing exclusion before generation.
- E2 keeps headings/columns listed below, literal cell text, deterministic case-insensitive sanitized 31-character sheet names and explicit partial consent. Empty/failed sheets and unavailable note/comment labels must be visible. E3 invalidates preview when source/scope/filter selection changes and keeps exclusions keyed by saved ID/host/key.

### Task E1: Source-aware export preview without global switching

**Files:** Create `server/lib/taskExport.mjs`, `server/routes/taskExportRoutes.mjs`, `tests/taskExport.test.mjs`; modify `server/jiraProxy.mjs`, `server/lib/jiraInstances.mjs`, `server/lib/jiraSearchHelpers.mjs`, `src/services/jiraClient.js`.

**Interfaces:** `collectTaskExport({sites,timezone="UTC",signal}) -> Promise<ExportSnapshot>`, where sites are `{instanceId,source:'local'|'team',scope:{projectKeys?|presetIds?},includeCompleted,priorities?,followUp?}` and exactly one nonempty scope type is required per site. `ExportSnapshot={exportedAt,timezone,commentScope:"Latest Jira comment only",sites:[{instanceId,displayName,siteHost,source,scope,status:'complete'|'partial'|'failed',message?,rows}]}`. Each row has `issueKey,summary,status,assignee,jiraDueDate,jiraUrl` and D2 selected-source metadata fields plus `localNote`, `localNoteStatus`, `teamNote`, `latestJiraComment`, `jiraCommentStatus`. Filters: optional nonempty `priorities:number[]` (integers 0–20), optional scalar `followUp:"now"|"next"`; omit for all values. Scope is exactly one nonempty unique array of `projectKeys:string[]` or positive integer `presetIds:number[]`; `includeCompleted` defaults false. Reject duplicate instance IDs and arbitrary JQL/rows/hosts. `exportedAt` and ISO `expiresAt` are UTC timestamps; submitted IANA timezone is retained after validation. `POST /api/task-export/preview` returns `{previewId,snapshot,expiresAt}`; `GET /api/task-export/sites/:id/scopes` provides safe project/preset choices for that saved site. All URLs are derived on the server from registry IDs, never client hosts.
