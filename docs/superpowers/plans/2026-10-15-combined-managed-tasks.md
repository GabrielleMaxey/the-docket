# Managed Combined Work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.

**Goal:** Make Combined Work a normal editable mixed-site task table with full My Metrics and a compact List option.
**Architecture:** Preserve active-site operations and add explicit saved-site context to the existing handlers/clients. Reuse ordinary editor logic behind composite row identities; reuse existing metrics and report UI with a dedicated combined local scope.
**Tech Stack:** Existing React18, Express, Node22, SQLite, optional PostgreSQL and node:test/esbuild; no new dependencies or classes.
**Spec:** docs/superpowers/specs/2026-10-15-combined-managed-tasks-design.md

## Global Constraints
- Managed tasks is the default; one mixed editable table with Jira site column, ordinary controls, full My Metrics, and optional List mode.
- Only unfinished issues assigned to currentUser on each selected saved site populate the task view. Report history retains its own existing assigned-work query semantics.
- Count each distinct hostname/issueKey once in workload totals; retain separately labeled saved-entry rows and local notes/planning values.
- One Combined Work goals scope and a dedicated Docket-level combined report archive; no arbitrary active-site owner.
- Preserve original active-site/generation guard. All combined nested reads, writes, uploads, mappings, metadata and jobs use captured saved-entry context with revision checking. Never activate a site to execute an operation.
- Local identity is saved-entry ID plus issue key; Team identity remains hostname plus issue key. Real Jira keys never become composite keys in API payloads or links.
- Reuse existing validation/editing/search/transport/hydration/report workflows. No speculative abstractions, new classes/dependencies, unrelated cleanup or live services/data.
- Test in a separate checkout with its own Node22 dependencies. The user's existing Electron/Vite worktree and native binary must remain untouched. Company Sonar remains blocked; no retry/bypass/green claim.

## Review Focus
1. Identical Jira keys/IDs and different mappings on sites A/B: edits, attachments, parent dates and selection must never cross sources (Tasks1–2).
2. Saved entry edited/deleted after loading or while a save is queued: reject stale context before any write, retain drafts; never substitute current active credentials (Tasks1–2).
3. Switching view/tab/site during pending reads and writes: cancel obsolete reads, preserve submitted save outcome/drafts, no whole-map browser-storage overwrite from another editor (Tasks1–2).
4. Duplicate saved entries for one actual issue: metrics count once but preserve distinct local values; partial/historical report inputs remain truthful (Tasks2–3).
5. Combined report goals/archive scope with overlapping numeric report IDs: combined read/delete/history cannot touch an ordinary site's archive (Task3).

Explicit operation headers: `X-Docket-Saved-Site` and `X-Docket-Saved-Revision`; both required together. Server-only request context lives on `req.docketOperation`. `getRequestOperationContext(req,fallback)` returns that or unchanged ordinary route context. Existing `withSiteOperation` implementation remains untouched; a composition wrapper delegates ordinary requests to it and accepts explicit saved contexts only on a method/path allowlist of the named operations below. Never fall back to active on malformed explicit headers.
- Allowed operations: existing issue status/assignee/date/comment, local metadata/bulk/images/pin, Team metadata/priorities/dates and health, attachment list/upload/limits, issue summaries/parent lookups, user search/resolve/myself, search/all, field-mapping reads and settings reads needed for hydration. Reads/writes use the same context within each handler. Return409 `SAVED_SITE_CONTEXT_CHANGED` for stale/removed/disabled context. Tests can inject synthetic transport/env.
- Collector keeps fixed assigned/open JQL, existing bounds/failures/cancellation. Rich fields use getJiraSearchFields for each site's mappings. No local draft mutation during collection.
